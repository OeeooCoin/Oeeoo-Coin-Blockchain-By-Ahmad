## FINDING (new, disclosed) — main-thread CPU burn ~50x the M17 binary, grows with height
- Evidence (samples file, CPU = utime+stime totals): leg-2 A 2.38s (08:18) -> 185.74s
  (08:43), B 2.49 -> 185.83s. Per-5-min burn: +16.3, +34.1, +36.6, +44.6, +51.7 s
  (A; B identical). Live: ~11.8% of one core per node (top TIME+ 3:24 @ 28:45 elapsed).
- M17 binary (same driver pattern, same heights): A 3.38 -> 24.6 s over ~100 min
  (~0.2 s/min); M18 soak (M17 binary) samples: 8.5 -> 11.08 s over 12 min at h~326-374.
  This binary burns ~10 s/min at h~100 — roughly 50x.
- Thread breakdown (/proc/PID/task/*/stat): essentially ALL of it is the MAIN thread
  (tid 2875: utime 19676 ticks of ~197 s total; every other thread <1 s). RPC
  workers, P2P threads are idle. Build config is NOT the cause: M17 ASan build
  was also Debug + identical sanitizer flags (checked both CMakeCaches).
- Experiment 08:47:16-08:48:16 UTC: driver SIGSTOPped 60 s (no blocks, no RPC).
  Main-thread utime delta: A +158 ticks (1.58 s), B +158 ticks. So the IDLE loop
  (Poll/dial) burns only ~1.6 s/min — NOT a spin. The burn is BLOCK-DRIVEN.
- Per-block main-thread cost (interval CPU minus 8 s idle baseline, /20 blocks):
  ~0.4 s/block at h~10 -> ~1.3 at h~30 -> ~1.4 at h~50 -> ~1.8 at h~70 ->
  ~2.2 s/block at h~90. It GROWS with height (height and time are confounded in
  this design; UTXO set also grows 1 coinbase/block).
- A and B burn identically, but getblocktemplate/submitblock run on A ONLY — so the
  cost is in the SHARED block receipt/validation/relay/store path on the main
  thread, not in template assembly or mining RPCs.
- Exact function NOT identified: no gdb, no perf on this VM; strace exists but the
  burn is user-time computation, not syscalls. Prime suspects (unproven): an
  O(height) scan in the block-acceptance path, or compact-block handling now
  active under real peering (the bridge dropped sendcmpct, forcing classic relay;
  real dialing negotiates it). Needs a profiler follow-up; NOT a correctness bug,
  does NOT block this soak, but at mainnet heights a linearly-growing per-block
  cost would be serious. (Driver pause disclosed: 4 blocks not mined 08:47-08:48.)

  +10.6 (h 115->173). So the burn ROSE to ~10 s/min by h~100 and then FELL to
  ~2.2 s/min after h~115 and stayed there. The "grows with height" reading in
  the previous note is WRONG and is replaced by this.

  building); the fall coincides with a QUIET VM (0.62-0.66 at 08:45/09:03).
